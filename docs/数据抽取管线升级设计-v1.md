│    │    backend ∈ {docling, mineru,           │
│    │           paddleocr_vl}(config 选择)     │
│    ├─ 图表取数 VLM: chart_reverse_vlm         │
│    └─ 低置信 → 回退规则管线                   │
└──────────────────────────────────────────────┘
        │ 七元组 Record（time/space/value/unit/indicator/source/note）

        ▼

### 2.2 路由与开关策略

配置项（新增 `data/pipeline_v2_config.json`，默认值如下）：

```json
{
  "structure_backend": "paddleocr_vl",
  "structure_enabled": true,
  "structure_pdf_types": ["scanned", "complex"],
  "chart_vlm_enabled": true,
  "chart_vlm_model": "qwen-vl-plus",
  "chart_rule_fallback": true,
  "schema_llm_enabled": true,
  "content_audit_enabled": true,
  "content_audit_sample_rate": 0.1,
  "bench_enabled": false
}
```

路由规则：
- **结构后端**：仅对"扫描件/低质量文本 PDF"启用（判定：pdfplumber 文本提取 < 30 字符/页 或
  页无文本则视为扫描件）；xlsx/csv/docx/pptx 仍走现有管线，不受影响。
- **图表 VLM**：chart_reverse 产出的记录如 `pipeline=chart_reverse` 且每图点数 < 2 或归一值
  ≥95% 与原点重合（规则法失效信号），触发 VLM 重取。
- **content_audit**：只吃 `evidence=HIGH_confidence` 或 `outlier_removed` 的记录抽样，避免
  审噪声档。
- 三个开关均可由 `run_pipeline.py --backend-config <json>` 覆盖；task_manager 读取同一配置。

## 3. 模块详细设计

### 3.1 M3-A 结构解析后端 `src/pipelines/structure_v2.py`

```python
def detect_pdf_kind(pdf_path: str) -> str:        # "scanned" | "text" | "complex"

    # render page → backend.parse_page(png) → {tables:[{rows, header, meta}], text_blocks}
    # → 遍历表格: 表头展开(多级表头合并) → 七元组
    # note 标注: pipeline=structure_v2; backend=<name>; conf=<model_self_confidence>
```

后端封装要点（统一接口 `parse_page(png_path) -> dict`）：
- **backend=paddleocr_vl**（首选）：PaddleOCR-VL 0.9B，输入页图 → 输出 markdown 表格 +
  说明；解析 markdown 表格为行列结构；模型文件放 `models/paddleocr_vl/`（首次启用下载，
  参考现有 PaddleOCR 嵌入手法的 `patch_paddlex.py` 流程）。
- **backend=docling**：`DoclingDocument` API，`convert_pdf` 输出 `dt.structured` 表格 +
  坐标；保留坐标用于与 GT 对齐（评测用）。
- **backend=mineru**：`magic_pdf` 提取表格+公式；处理公式/复杂版面更稳。
- 三后端**不做并行**，只按配置启用其一；`check_deps_v2.py` 报告可用性，全部不可用时
  `structure_enabled` 自动 false（静默回退现状，日志标注）。

规则约束（防止垃圾进库，与现有管线一致）：
- 数值必须能被 `float()` 解析；表头行/汇总行判别沿用 `xlsx_robust` 的多级表头合并逻辑
  （抽成公共函数或复制其"行列合并"判定，避免两处漂移）；
- 指标经 `match_schema` 未命中后续补 `schema_llm`（见 3.4）；
- 每次调用记 API 用量：`note=...,api=paddleocr_vl:0.9B:page=12`。

### 3.2 M3-B 图表取数 VLM `src/pipelines/chart_vlm.py`

```python
def parse_charts_vlm(pdf_path, page_num, llm, model="qwen-vl-plus") -> list[Record]:
    # 页图(300dpi) → 单图区域(可叠加 OpenCV ROI 提示) → VLM 一次一图
```

Prompt 模板（system+user 两段，输出**严格 JSON**，禁止散文）：

```
system: 你是经济统计年鉴图表取数引擎。只输出 JSON，禁止输出 JSON 以外的文字。
user:
  请把这张图表转成结构化数据。
  图表形态：{bar/line/stacked/pie}（如不确定填 "unknown"）
  输出 JSON：
  {
    "chart_title": "字符串或 null",
    "axis": {"x_label": "...", "y_label": "...", "x_unit": "...", "y_unit": "...", "x_ticks": [...], "y_ticks": [...]},
    "series": [{"name": "...", "values": [{"x": "2020", "y": 1234, "unit": "千元"}]}],
    "confidence": 0.0-1.0,
    "uncertainties": ["哪些数值/单位/年份无法确认"]
  }
  硬规则：
  1) 数值必须逐点从图上读出；不确定就标到 uncertainties，禁止推测或取整美化；
  2) x_ticks 若为年份，必须转成字符串年份；
  3) 单位优先读坐标轴标注；图上没有单位则 unit=null 并写进 uncertainties。
```

后处理：
- `confidence>=0.7` → 直接入七元组（`pipeline=chart_vlm`，`conf` 进 note）；
- `0.4<=confidence<0.7` → 入七元组但 `note` 标 `pending_review`（数据面板自动待审）；
- `<0.4` 或解析失败 → 回退现有 `chart_reverse`（规则）并在日志计数。
- **修复"文档与实现不一致"**：此模块落地后，提交文档 P7 的"qwen-vl-max"描述改为真实调用
  （qwen-vl-plus 或按页数/复杂度自动升级 qwen-vl-max），并附调用量统计。

- `parse_all_sources(input_dir, llm, config=None)`：参数扩展 v2 config；PDF 分支逻辑：

## 4. 评测基准（对标 OmniDocBench 的自建小基准）

### 4.1 样本与 ground truth（`data/bench_gt/`）

20 页，5 类场景 × 4 页（从本地真实来源选取，保持"真实资料来源"属性）：

| 场景 | 来源 | 页示例 |
|---|---|---|
| A 扫描页数字表格 | `中国火炬统计年鉴2024.pdf`（扫描版） | 已人工核验的 1-3/1-6 表所在页 |
| B 多级表头表格 | `第1部分/*.xlsx`（另存 PDF 后入测） | 1-3_各高新区企业主要经济指标 |
| C 图表页（柱/线/堆叠） | 年鉴 PDF 图表页 | 收录值可人工读数的页 |
| D 长时序表 | `1-1_...`、`6-1_...` 长表 | 1995–2024 序列页/表 |
| E 混合版面（表格+图+注） | `主要指标解释.pdf` | 表格+解释文字页 |

每页 GT 文件 `gt/<scene>_<page>.json`（人工标注，含标注人/日期）：

```json
{
  "page": "A-2024-003",
  "n_tables": 1,
  "tables": [{
    "cell_ref": "p3-t1",
    "n_rows": 31, "n_cols": 8,
    "header2": ["园区名称", "营业收入(千元)", "…"],
    "units": {"营业收入": "千元"},
    "gt_records": [{"time": "2023", "space": "北京·中关村", "indicator": "营业收入",
                    "value": 123456, "unit": "千元", "source_hint": "p3-t1-r4-c2"}],
    "notes": "表头三级合并；无法确认字段: 无"
  }]
}
```

### 4.2 指标定义（`scripts/bench_parse.py` 计算）

- **表格结构匹配**：单元格对齐（按坐标/行列合并）→ 结构精确率 Precision、召回 Recall、F1；
- **数值 F1**：以 (time, space, indicator) 三元组对 GT 匹配，正确值在 ±1%（同一指标多单位
  先做单位归一再比较）；
- **单位正确率**：unit 与 GT 一致数 / GT 记录数；
- **未确认率**：模型/管线自己标 `cannot_judge` / 全部记录（越低越好但非零）；
- **可回溯率**：note 中含页码/表号/行号占比。
- 输出 `output/eval/bench_report.md` + `bench_scores.json`；报告含"新管线 vs 现行管线"两列。

### 4.3 验收阈值（第一版）

- 场景 A（扫描表格）数值 F1 ≥ 现行管线 +0.15 或 ≥ 0.80（以现行 0.65 基线为参照，实测后校准）；
- 场景 C（图表）VLM 链路成功率 ≥ 0.8（输出可解析 JSON 且 confidence ≥ 0.6 比例）；
- 全库 `pending_review` 占比 ≤ 15%；
- 新管线不劣化：现有 smoke 测试 100% 通过，七元组零 schema 破坏。

## 5. 上下文工程与 Qwen 调用矩阵（对齐提交文档 P7）

| 任务 | 模型 | 上下文（注入顺序） | 输出约束 | 降级链 |
|---|---|---|---|---|
| M1 需求解析 | qwen-plus（已有） | 研究需求 → 字段字典 | JSON Schema | 无 key → 规则 |
| 图/表单解析（新） | qwen-vl-plus（复杂页自动 qwen-vl-max） | 页图 + 系统约束 + 字段字典摘要 | 严格 JSON（图见 3.2） | VLM 不可用 → OpenCV 规则 |
| 结构解析后端 | 无需 LLM（专用模型） | — | — | 后端缺 → 现有 PaddleOCR |
| schema 补层（新） | qwen-plus（bailian） | 未匹配指标 + 字典前 50 标准名 | 多选一 JSON | → 保持 unmatched |
| 内容抽检（新） | qwen-plus | 记录 + 类型错误码表 | 单标签 JSON | → 统计异常结果 |
| 假设生成/评审 | qwen-plus → qwen-turbo（已有） | 不变 | 不变 | → 本机 OpenCode → 规则 |

防编造三原则（沿用项目既有门禁）：数值一律由解析代码在真实图像/文件上计算或读出，模型写
`confidence` 与 `uncertainties`；未命中字典不放行新造标准名；所有 LLM 参与项在 note 记录
模型名与调用量。

## 7.1 实现记录（2026-09-02 落地）

> 本设计与实际实现的差异登记（实现优先于文档）：

1. **结构解析后端新增 `vlm_ocr`（DashScope qwen-vl*）为实际默认**：
   - 环境探测（`scripts/check_deps_v2.py`）结果：torch/docling/mineru 已安装，但 **docling
     首次使用需从 HF 下载模型，本机 HF 不可达**（LocalEntryNotFoundError）；mineru 同需
     模型下载；PaddleOCR-VL 本地模型未内置。因此 `auto` 路由实际落在 `vlm_ocr`
     （复用项目已有 DashScope key），docling/mineru 保留为"模型缓存可用时"的备选后端。
2. **图表取数不改用裁剪图**：实测 ROI 裁剪（203×203px）会丢失轴标/图例上下文，模型
   输出不可解析；改为 ROI 检测只用于"判断该页是否有图表"，取数时传整页图。
3. **DashScope 视觉调用通道**：`Generation.call`（400: url error，dashscope 1.27.2 不接受
   base64 图像）→ 改用 OpenAI 兼容接口 `compatible-mode/v1/chat/completions` +
   `image_url.data:image/png;base64`（实测可用，封装在 `llm_interface.call_vision`）。
4. **xlsx_robust 表头修复（基准暴露的真实缺陷）**：年鉴 xlsx 前 2 行为标题（中英），原实现
   直接取 `rows[0]` 当表头 → 1-3 表解析 0 条。新增 `_find_header_row`（前 8 行打分选表头）
   + 多级表头子行合并 + 指标名去脚注符号（利润总额①→利润总额）。
5. **存量 bug 修复（v2 接线后暴露）**：`text_ie.py` 缺 `import json`；`ocr_pipeline` 与
   paddleocr 3.4 不兼容（ValueError + PaddleX 模型格式变化）→ 优雅降级并提示
   PaddleOCR_V5=1 / structure_v2。
6. **基准现状**：场景 B（1-3 多级表头）与 D（6-1 长时序）GT 已标注并实测
   **key 召回 1.000 / 值精度 1.000 / 单位准确 1.000**（20 条 GT）；场景 A/C/E（扫描页、
   图表页、混排页）GT 需视觉标注——已按标注协议登记为 pending。
7. **LLM key 回退**：`LLMInterface()` 无参时从 `server_data/llm_config.json` 回退读取
   （CLI 脚本可直接用）；`api_key=""` 仍为显式禁用。
