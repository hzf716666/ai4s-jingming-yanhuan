# 知识图谱增量构建设计 v1 —— 规则分层 + AI 核验 + 增量构建

> 景明研环 · 2026-09-01
> 目标: AI 抽取进来的新数据,**增量**地"长进"知识图谱——能连上已有节点就连边, 连不上才新建节点, 边界情况由 AI 核验, 绝不全量重构。
> 现状: 图谱页读静态 `fkg_graph_view.json`(218节点/729边, FKG双集群研究图), 抽取链路(8787 task_manager M6 / OECD research MCP)只同步到数据面板+地图, **没有图谱同步**。

---

## 1. 核心原则

1. **增量**: 只处理 `fact_records.id > watermark` 的新纪录, 永不重扫全库。
2. **幂等**: 节点/边有唯一键, 重复记录只更新权重, 不产生重复。
3. **规则优先, AI 只核验边界**: 确定性匹配走规则, 模糊/新建/噪声交 AI 核验。
4. **可回滚**: 每次变更记 changelog(节点/边/裁决), merge/reject 可逆。
5. **失败不阻塞**: AI 不可用时保持 provisional, 抽取流程不受影响。

## 2. 存储(增量可写)

SQLite(与 integration.db 同库, 独立前缀表):

| 表 | 键 | 关键字段 |
|---|---|---|
| `kg_nodes` | `key` (PK) | name, category, node_id(视图id), attrs_json, status, source, created_at |
| `kg_edges` | (source_key,target_key,edge_type) PK | node_id对, weight, status, source |
| `graph_sync_meta` | `key` PK | value (watermark=已处理最大 fact_records.id) |
| `graph_reviews` | item_key PK | verdict(keep/merge/reject), target_key, reason, model, confidence, at |

视图: `fkg_graph_view.json`(页面现读) 由本批变更**增量合并**(append/update), 不重建整个文件。

### id 约定(避免与 FKG 冲突)

FKG 现有前缀: `reg_`(空间) `clu_`(集群) `stc_` `ind_`(**产业**, 如 ind_新一代信息技术 — 注意不是经济指标) `meas_` `pol_` `ins_` `act_` `stg_`。

数据来源的新节点另起前缀:
- `dind_<规范化指标>` — 经济指标(GERD占GDP比重/营业收入…)
- `dreg_<规范化空间>` — 数据空间(韩国/武汉高新区…); 若 L1 命中 FKG `reg_` 同名空间 → **直接复用 reg_ 节点**(不新建)

## 3. 流水线(每批增量记录走一遍)

```
fact_records (id > watermark, 一批 ≤500)
  │
  ▼
L0 标准化 ── indicator/space/time 规范化(别名/单位/市省尾缀/crosswalk/GIS)
  │
  ▼
L1 规则层(确定性) ── 连 or 建, 五档判定
  ├─ A 精确命中已有节点 ──────→ 连: 建/加边(weight++)
  ├─ B 父挂(子→父关系) ───────→ 连: 只加边(located_in/measured_by), 不建节点
  ├─ C 模糊近邻(向量>阈值) ───→ 暂连 + pending_verify → L2
  ├─ D 无任何命中 ────────────→ 新建节点(status=provisional) → L2
  └─ E 噪声(数字垃圾/无实义) ──→ 丢弃(写 graph_reviews=rejected)
  │
  ▼
L2 AI 核验(仅 provisional/pending_verify, 增量批 ≤20)
  └─ merge(→target) / keep(→类别+父边) / reject, 落 graph_reviews
  │
  ▼
L3 物化 ── 本批变更增量合并进 fkg_graph_view.json(及 dist 副本), 更新 watermark
```

## 4. 关键判定: 什么数据"连已有节点", 什么数据"新建节点"

### 4.1 连(attach)的判据 —— 与已有节点是**同一个真实世界实体**或**它的子属性**

| 情形 | 例子 | 动作 |
|---|---|---|
| 同名/别名变体 | 上海/上海市/SHANGHAI; 营业收入_千元/营业收入①/(100 million) | 归一后命中 → 连指标/空间节点, 加边 |
| 单位/口径差异 | GERD占GDP比重(%) vs 研发经费(本币) — 同一指标不同口径 | 连同一 Indicator 节点(unit 记在边上) |
| 子—父关系 | 武汉高新区→武汉市→湖北省; 襄阳高新区→襄阳市 | 连边 located_in, **不新建父节点** |
| 指标—空间赋值 | GERD占GDP比重 × 韩国(已有该指标节点) | 指标节点已存在 → 只加 Indicator–Region 边 |

### 4.2 新建(create)的判据 —— 是**新的真实世界实体**, 且现有图中无表示

| 情形 | 例子 | 节点类别(规则初判) |
|---|---|---|
| 新空间单元 | 韩国/英国/法国(此前无) | Region(`dreg_`) |
| 新经济指标 | GERD占GDP比重(若此前无) | Indicator(`dind_`) |
| 新产业/集群 | 医药/显示(从指标名或来源表提取) | Industry/Cluster |
| 新工具/政策/主体 | 专项基金/行动计划(若抽取层遇到) | Instrument/Policy/Actor |

类别初判规则: 指标词(营收/经费/占比/企业数…)→Indicator; 地理词或有 adcode/GIS → Region; 产业词(汽车/显示/生物医药…)→Industry/Cluster; 基金/贷款/计划/政策 → Instrument/Policy; 无特征 → Unknown(交 L2)。

### 4.3 拒绝(不建节点) —— 无实体价值

纯数字 indicator 垃圾(zone_facts 里已见 '10009'), 超长碎片, 单位串, 无实义词。规则 E 档拦 + AI 复核。

### 4.4 派生边(两类都做)

- 同一来源文件/表抽出多条记录 → 它们各自 indicator/space 节点之间 `co_mentioned` 边(增量)。
- 记录→证据。每条新记录在(指标,空间)已有边时 value 不重置, weight++。

## 5. L2 AI 核验(增量批, 复用现有 LLM)

- 输入: 候选 item + 证据(原记录 source/table/值) + L1 理由, 每批 ≤20。
- 输出 JSON: `{item_key, verdict: keep|merge|reject, target_key?, category?, parent?, reason, confidence}`
- 阈值: confidence<0.7 或 LLM 失败 → 保持 provisional 并挂 `pending_review`(数据面板人工裁断, 与 record_reviews 呼应)。
- 模型: 8787 `llm_interface`(DashScope GLM/deepseek, 现有 /api/llm-config 配置) 优先; 不可用降级本机 opencode。
- 实体近邻(C 档)用 BGE-M3 向量(假设评审同款库)后台线程算, 不阻塞主流程。

## 6. 接入点(自动, 无需人工)

- `sync_oecd_to_panel.py`(research MCP 的自动同步) 末尾 → 调增量图谱同步。
- `task_manager.py` M6(工作台抽取落库后) → 调增量图谱同步。
- 两者都只读 `id > watermark`, 幂等。
