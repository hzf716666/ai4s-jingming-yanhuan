# 数据整合前端设计 v3 — 三页独立 + 抽取融入 AI + 数据管理

> 景明研环 · 2026-08-31
> 原则：页面极简（全屏内容 + 底部一两条控制栏）、抽取是任务不是页面（AI 代劳）、数据资产可追溯（管理页看文件→数据→地图的链路）

---

## 一、页面结构：三个独立页面

```
侧边栏「数据整合」
├── 数据地图   → /data/map      （全球可缩放地图 + 底部指标栏）
├── 知识图谱   → /data/graph    （力导向图 + 搜索/类型筛选）
└── 数据管理   → /data/manage   （文件 → 抽取数据 → 上地图的链路与投票融合）
```

- 没有"一键问 AI"按钮——需要分析直接在对话框里问 Qoder 即可。
- 保留实体回链：AI 回答中的园区/指标名渲染为可点击标签 → 跳转地图/图谱定位（见第六节）。

---

## 二、数据地图（/data/map）— 全屏地图

模仿火炬数据地图 idx.html 的形态：**全屏地图，无侧栏无顶栏遮挡，只留底部控制栏**。

```
┌────────────────────────────────────────────────────────────────────────┐
│                                                                        │
│               ECharts 地图（全屏主体，无任何侧边框）                     │
│               - 全球底图 → 滚轮/双击逐级放大：全球 → 中国 → 湖北省      │
│               - 层级自动切换数据粒度：                                  │
│                 全球：国家/省聚合点；中国：省/园区点；湖北：园区点位     │
│               - 选中指标后：点位高度/大小 = 指标值（3D 柱或气泡）        │
│                                                                        │
├────────────────────────────────────────────────────────────────────────┤
│  栏 1（指标）：[入统企业数] [营业收入] [R&D经费] [技术合同额] [净利润] … │
│  （点击切换，点位高度随之更新）                                         │
│  栏 2（产业链，可选第二栏）：[上游] [中游] [下游] —— 按产业环节着色      │
└────────────────────────────────────────────────────────────────────────┘
```

- 交互：点击园区 → 小气泡卡片（名称 + 当前指标值 + 年份），点空白关闭。
- 年份：右上角极小浮标滑条（2019–2026），其他全部隐藏。
- 数据：`h3_cube_res5.json` + 园区宽表面板；产业链环节来自技术领域构成（8-4）与集群名单。
- 只有这两条栏，无关控件一律不加。

## 三、知识图谱（/data/graph）— 全屏图

同样极简：图占满，控制只留一条顶栏。

```
┌────────────────────────────────────────────────────────────────────────┐
│  顶栏（单行）：[搜索框] [节点类型下拉：全部/Indicator/Region/Cube/…]     │
├────────────────────────────────────────────────────────────────────────┤
│              力导向图（全屏主体，canvas）                               │
│              仅渲染非 Cell 节点（~580 个），节点按类型着色，悬浮显示名称  │
│                                                                        │
│              点击节点 → 右下角小面板（不挡图）：                        │
│              名称 · 类型 · 描述/统计 · 邻接分组列表                     │
└────────────────────────────────────────────────────────────────────────┘
```

- 数据：`graph_v3.json` 精简为 `graph_web.json`（非 Cell 节点 + Cell 聚合计数）。
- 不做：关系筛选、布局切换、密度滑条。

## 四、数据抽取 — 融入 AI，无独立页面

数据抽取本质是**任务**，不是展示结果——所以不设页面，把它变成 **Qoder 智能体的一项技能（skill）**：

```
用户在对话框说："把这份 PDF 里的火炬数据抽出来"

  Qoder 智能体（对话内）
      │ 调用技能「数据抽取」（新 skill，Agent 工具触发）
      ▼
  数据抽取执行链（由 agent 驱动）：
      上传/定位文件 → 调 8787 抽取后端（OCR/解析管线）或本地管线
      → 七元组结果写回工作区 data/ 目录（CSV + JSON）
      → 在对话中汇报："已抽取 12 张表、608 条记录，结果在 data/xxx.csv"
```

- 用户在**对话框里自然描述**即可触发（"帮我抽取这份文件"），不用学任何界面。
- 抽取产物自动进入工作区 → AI 可继续追问分析（"哪些指标异常？"），数据管理和地图自动可读。
- 前端只需保留一个**极简上传入口**（把本地文件送进工作区/后端），没有任务管理界面。

## 五、数据管理（/data/manage）— 文件 → 数据 → 地图的链路

这是新增的核心页面：展示**每个文件产出了什么数据、这些数据如何落到地图上、多源冲突如何裁决**。

```
┌────────────────────────────────────────────────────────────────────────┐
│  顶栏：[文件筛选] [指标筛选] [来源状态：原始/换算/派生]                 │
├──────────────────────────────┬─────────────────────────────────────────┤
│  左栏：文件列表               │  主区：选中文件的抽取明细                │
│  ├─ 火炬年鉴2025.xlsx  ✓ 608条│  ┌────────────────────────────────────┐ │
│  ├─ 基地名单.pdf      ✓ 48条  │  │ 七元组表格（时间/空间/数值/单位/     │ │
│  ├─ 统计公报.docx     ✓ 12条  │  │ 指标/来源/证据链）                  │ │
│  ├─ 扫描年鉴.pdf      ⚠ 0条   │  │ 异常/缺失/冲突行着色                │ │
│  └─ …（按来源分组）           │  └────────────────────────────────────┘ │
│                               │  ┌────────────────────────────────────┐ │
│  每个文件显示：                │  │ 多源投票融合明细（选中指标时）：     │ │
│  ✓ 抽取状态/记录数            │  │ 指标「营业收入/湖北省/2024」          │ │
│  ✓ 产出指标集合（标签云）      │  │  ├ 来源A(年鉴xlsx)  = 12.3 亿元  ★HIGH│ │
│  ✓ 是否已上地图（✓/未用）      │  │  ├ 来源B(扫描PDF)  = 12.4 亿元       │ │
│                               │  │  ├ 来源C(公报)      = 10.1 亿元  剔除  │ │
│                               │  │  └ 裁决结果：12.34 亿元（证据链3方）  │ │
│                               │  └────────────────────────────────────┘ │
├──────────────────────────────┴─────────────────────────────────────────┤
│  底部：数据上地图示意条 —— 地图图层 ← 哪些文件/来源贡献（点击图层查看） │
└────────────────────────────────────────────────────────────────────────┘
```

- **文件 → 数据**：每个文件一行，展开看抽取记录与产出指标。
- **数据 → 地图**：底部示意条显示"园区点位层 ← 年鉴xlsx + 名单PDF；指标热力 ← …"，说明数据是怎么放上地图的。
- **多源投票**：同一指标多来源冲突时，展示四档证据链裁决明细（HIGH/outlier_removed/CONFLICT_avg/MEDIUM），用户能看见"谁被采纳、谁被剔除、为什么"。
- 数据来源：抽取后端登记 + 工作区 data/ 目录扫描 + 融合台账 JSON。

## 六、AI 回链（保留）

- 前端维护实体名表（园区名/指标名/图谱节点名，来自图谱与园区 JSON）。
- 渲染 AI 消息时匹配已知实体 → 渲染为可点击标签 → 点击跳转地图/图谱并定位。
- 用户看到的体验：AI 回答提到"武汉东湖高新区" → 点一下就到地图上这个园区。

---

## 七、实施顺序

1. **数据地图页**（最大件）：ECharts 全球底图 + 缩放 + 底部指标栏 + 年份浮标，接 h3_cube_res5.json 与园区面板。
2. **数据抽取融入 AI**：新增「数据抽取」skill（agent 触发 8787 后端/本地管线）+ 极简文件上传入口 + 结果落盘工作区。
3. **数据管理页**：扫描工作区 data/ + 融合台账，文件→数据→地图链路 + 投票融合明细。
4. **知识图谱页**：graph_web.json + 力导向 + 搜索/类型筛选 + 节点面板。
5. **实体回链**：实体名表 + 消息高亮跳转。
